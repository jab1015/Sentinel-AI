# 1. Purpose

This Software Requirements Specification (SRS) defines the functional and non-functional software requirements for Sentinel AI.

It serves as the primary engineering specification for software development, testing, validation, and future maintenance.

---

# 2. Scope

Sentinel AI is a Windows desktop application that continuously monitors operating system activity, network behavior, security settings, and application execution while providing AI-assisted explanations and evidence-based threat analysis.

---

# 3. Definitions

| Term | Definition |
|------|------------|
| Event | Any monitored activity generated by Windows or Sentinel AI |
| Alert | A user-visible notification generated from an event |
| Threat | Activity determined to present elevated risk |
| Confidence Score | Sentinel AI's confidence in its assessment |
| Risk Score | Estimated severity of a detected behavior |
| Timeline | Chronological history of monitored events |

---

# 4. Product Overview

Sentinel AI consists of multiple software components working together:

- User Interface
- Monitoring Engine
- Threat Engine
- AI Analysis Engine
- Database
- Logging Service
- Notification Service
- Update Service

Each component shall operate independently while communicating through well-defined interfaces.

---

# 5. Functional Requirements

## FR-001 Dashboard

The system shall display:

- Security Score
- Current Security Status
- CPU utilization
- Memory utilization
- Disk activity
- Network activity
- Firewall status
- Defender status
- Number of alerts
- Active monitoring status

Refresh interval shall not exceed one second.

---

## FR-002 Process Monitor

The system shall continuously monitor:

- Running processes
- Parent processes
- Child processes
- Executable path
- Process ID
- CPU usage
- Memory usage
- Digital signature
- Publisher

The monitor shall detect process creation and termination.

---

## FR-003 Network Monitor

The system shall monitor:

- TCP connections
- UDP endpoints
- Listening ports
- Remote IP addresses
- Local IP addresses
- Ports
- Connection state
- Owning process

Connections shall update in near real time.

---

## FR-004 Windows Security

The application shall monitor:

- Microsoft Defender
- Windows Firewall
- Windows Update
- Secure Boot
- SmartScreen
- BitLocker

---

## FR-005 Event Logging

Every monitored event shall include:

- Event ID
- Timestamp
- Event Type
- Severity
- Source
- Description

Events shall be written to SQLite.

---

## FR-006 Notifications

Notifications shall support:

- Information
- Recommendation
- Warning
- Critical

Users shall be able to configure notification preferences.

---

## FR-007 AI Explanations

The AI system shall generate explanations containing:

- Summary
- Evidence
- Confidence
- Recommended Action

The AI shall distinguish facts from recommendations.

---

## FR-008 Threat Detection

The system shall detect:

- Unsigned executables
- PowerShell abuse
- Registry persistence
- Startup persistence
- Scheduled task creation
- Suspicious services
- Temporary-folder execution
- Unusual outbound connections

---

## FR-009 Search

Users shall search:

- Events
- Processes
- Connections
- Alerts
- Threats

Search results shall return in less than one second for normal datasets.

---

## FR-010 Reporting

Users shall generate reports including:

- Security summary
- Timeline
- Threat history
- Connection history
- Process history

Reports shall support export in PDF, HTML, CSV, and JSON formats.

---

# 6. Non-Functional Requirements

## Performance

Target idle CPU:

<1%

Target memory:

<200 MB

Application startup:

<5 seconds

Dashboard refresh:

<1 second

Database queries:

<500 ms

---

## Reliability

Sentinel AI shall:

- Recover gracefully from failures.
- Continue monitoring after recoverable errors.
- Prevent data corruption.
- Maintain database integrity.

---

## Availability

The monitoring engine shall automatically restart after unexpected failure.

---

## Maintainability

The software shall:

- Use modular architecture.
- Support dependency injection.
- Support automated testing.
- Minimize component coupling.

---

## Scalability

The architecture shall support future additions without requiring redesign.

Future capabilities include:

- Enterprise management
- Multiple computers
- Cloud synchronization
- Mobile companion applications

---

# 7. Security Requirements

The application shall:

- Verify digital signatures where available.
- Store configuration securely.
- Validate updates before installation.
- Detect tampering.
- Log privileged operations.
- Use least-privilege principles whenever possible.

---

# 8. Privacy Requirements

The application shall:

- Operate locally by default.
- Require consent before cloud synchronization.
- Allow users to delete stored history.
- Support export of user data.
- Document all telemetry.

---

# 9. Database Requirements

SQLite shall store:

- Events
- Alerts
- Threats
- Connections
- Processes
- Settings

Database migrations shall be version controlled.

---

# 10. Logging Requirements

Structured JSON logs shall include:

- Timestamp
- Component
- Severity
- Event ID
- Message
- Exception information (when applicable)

Logs shall support configurable retention periods.

---

# 11. User Interface Requirements

The UI shall:

- Support light mode.
- Support dark mode.
- Support keyboard navigation.
- Support screen readers where practical.
- Scale correctly on high-DPI displays.

---

# 12. Update Requirements

Sentinel AI shall:

- Detect available updates.
- Verify update signatures.
- Support automatic updates (optional).
- Support manual update mode.

---

# 13. Error Handling

Errors shall:

- Be logged.
- Display understandable messages.
- Never expose sensitive system information.
- Provide recovery guidance where possible.

---

# 14. Testing Requirements

Every software module shall include:

- Unit tests
- Integration tests
- Regression tests
- Performance validation

Major releases shall undergo manual validation.

---

# 15. Acceptance Criteria

Sentinel AI Version 1.0 shall successfully:

- Launch on supported Windows versions.
- Monitor processes.
- Monitor network activity.
- Display Windows security status.
- Store events in SQLite.
- Generate structured logs.
- Display live dashboards.
- Handle extended operation without crashes.
- Meet performance targets.

---

# 16. Traceability

Every functional requirement shall be traceable to:

- Source code
- Unit tests
- Integration tests
- User documentation
- Release notes

Requirement identifiers shall remain stable across future revisions.
